Responsive & breakpoints

The site is fluid, not fixed. Headings and lead text scale with clamp(), so there are no separate "mobile sizes"; layout reflows at two breakpoints. Every page must ship the viewport meta.

Content width
--maxw 1120px, centered, 28px gutters (.wrap); .narrow 760px for prose
≤ 860px · primary
Nav → hamburger, mega-menus → plain links; feature / cards / pillars grids → 1 column; footer → 2 columns; walkthrough stacks (sticky index hidden); journey rail scrolls sideways
≤ 520px · small phone
Small-phone tweaks; footer stays 2-up, everything else already single-column
Fluid type
Headings + .lead use clamp(), they shrink smoothly with the viewport, no per-breakpoint font sizes
Hero model
The animated SVG scales via viewBox + preserveAspectRatio; it gets dense at phone width (a mobile-simplified hero is a tracked follow-up)
Required on every page: <meta name="viewport" content="width=device-width, initial-scale=1">. Without it, mobile browsers render the page at desktop width and zoom out. Verified: no horizontal overflow at 375px.

Brand & logo

The Stormpine wordmark. On the site it is embedded inline and inherits currentColor, so it recolours with the theme automatically, near-black in light, near-white in dark. Standalone SVG files exist for external use.

Inline · currentColor (recolours with theme)
Assets & usage: on-site use the inline currentColor wordmark (the LOGO constant in app.js). For external/embedded use, the standalone files are assets/stormpine-logo-black.svg (light backgrounds) and assets/stormpine-logo-white.svg (dark). See assets/README.md. Keep all three in sync if the mark changes.

Iconography

One line-icon family across nav, mega-menus and accents. 24×24 viewBox, 1.6px stroke, round caps & joins, no fill, and currentColor so each icon takes the surrounding text colour (accent on hover in the mega-menu). Defined in app.js; used at 18px in the nav.

Voice & guardrails

The rules that keep copy and design on-brand. When in doubt, choose the more restrained option.

  • CRM, not tracker

    Relationships are the primary object; opportunities flow from them. Avoid "job application tracker", "resume builder", "career hacks".

  • Executive & understated

    Calm control, discretion, preparedness. Never hustle-culture, gamification, or consumer-grade playfulness.

  • Grounded AI only

    AI assists, grounded in the user's own record. Don't headline unproven claims (automated influence analysis, auto-generated briefings).

  • Private by design

    Career data is sensitive. Copy leads with discretion: you own your record, explicit and revocable sharing.

  • No em dashes

    House style: use commas, colons, parentheses or separate sentences. A hyphen for compounds and 2-3 ranges is fine.

  • Nordic-native

    Default context is Denmark/Nordics: recruiters, a-kasser, board conventions, Danish hiring norms.
